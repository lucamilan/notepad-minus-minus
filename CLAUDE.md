# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Notepad Minus Minus v2: a notepad that runs entirely in the browser. Notes are encrypted with a user passphrase and stored only in the browser (IndexedDB); nothing is ever sent over the network. It is an installable PWA that works offline. Published on GitHub Pages at https://lucamilan.github.io/notepad-minus-minus/.

The rewrite was done in phases F0–F9 (all complete), one PR each, described in `docs/piano-v2.md` (decisions, phase scope, status and accepted limits). Read its "Stato" section before changing behaviour.

The v1 (Blazor WebAssembly, .NET 7) is archived on branch `legacy/blazor-net7`, tag `v1-blazor-final`. Do not port code from it; it is only a reference for feature parity.

## Commands

Node 22 (`.nvmrc`), npm with exact versions (`.npmrc` has `save-exact=true`).

```sh
npm ci
npm run dev          # Vite dev server (no CSP in dev, see below)
npm run build        # typecheck + production build in dist/
npm run preview      # serve dist/ (CSP and service worker active)
npm run lint         # ESLint (typescript-eslint strict)
npm run typecheck    # tsconfig.json (browser code) + tsconfig.node.json (configs, e2e) + tsconfig.sw.json (service worker)
npm run format       # Prettier; CI runs format:check
npm test             # Vitest unit tests in tests/ (jsdom)
npx vitest run tests/smoke.test.tsx   # single test file
npm run test:e2e     # Playwright on Chromium + Firefox against the built dist/ (run build first)
npx playwright install chromium firefox   # once, to get the e2e browsers
```

## Architecture and security rules

Stack: Preact + `@preact/signals`, TypeScript strict, Vite, CodeMirror 6, markdown-it + DOMPurify, `idb`, Web Crypto, a hand-written service worker. No WebAssembly, no PWA plugin or Workbox.

- **CSP** is a `<meta>` tag injected at build time by the `notepad:csp` plugin in `vite.config.ts` (GitHub Pages can't send headers; Vite dev needs inline scripts and WebSocket, so dev runs without it). It enforces `default-src 'none'`, `script-src 'self'`, `connect-src 'self'` and **Trusted Types** (`require-trusted-types-for 'script'; trusted-types dompurify notepad-sw`): the only policies are DOMPurify's own and `notepad-sw` (`src/features/pwa/update.ts`), which turns exactly the `sw.js` URL into a `TrustedScriptURL` for `serviceWorker.register()` (a Trusted Types sink) and throws on anything else. Don't add others. Any change that breaks it fails `e2e/csp.spec.ts`.
- **CodeMirror lives in a shadow root** (`src/features/editor/Editor.tsx`): only there does style-mod use constructed stylesheets (`adoptedStyleSheets`); mounted on the document it would inject a `<style>` tag that `style-src 'self'` blocks. Editor colors come from the page's CSS variables, which cross the shadow boundary. `e2e/csp.spec.ts` asserts no `<style>` tags and that editor styles actually apply.
- **Theme**: `public/theme-boot.js` (plain script in `<head>`, allowed by `script-src 'self'`) applies the saved `data-theme` before first paint; `src/features/settings/theme.ts` owns the signal and persistence. Keep the storage key in sync between the two.
- **Accessibility**: modal panels use native `<dialog>` + `showModal()`; the opener restores focus on close. Menus follow the ARIA menu-button pattern (see `src/app/AppBar.tsx`). `e2e/a11y.spec.ts` covers keyboard behavior.
- **Storage** (`src/features/notes/`): IndexedDB database `notepad-minus-minus-cifrato` (`DB_NAME`; stores `notes`, `meta`) opened via `idb` by the vault (`src/features/crypto/vault.ts`). The old plain database `notepad-minus-minus` (`LEGACY_DB_NAME`, F2–F6) is only read by the legacy migration and then deleted. Schema changes go through the ordered `MIGRATIONS` array in `database.ts`: never edit a published migration, append a new one. Every record is `{ id, format, payload }`: the `NoteCodec` (`codec.ts`) turns a `Note` into a payload and also encodes `meta` values (`encodeMeta`/`decodeMeta`); the app uses the AES-GCM codec, `plainCodec` is only for the legacy migration and unit tests. `repository.getMeta/putMeta` always go through the codec and refuse the `keyring` key (the clear keyring has its own accessors in `keyringStore.ts`); a meta value that fails to decode reads as `undefined`. No indexes on note fields (they would leak metadata). The repository never overwrites unreadable records; first-run sample creation is atomic (`addIfEmpty`) so two tabs can't duplicate it. On `versionchange` the connection closes itself and the UI asks to reload.
- **Autosave** (`src/features/notes/autosave.ts`): always on, no toggle. Editor changes go through `editNote` (in-memory update + `modifiedAt`), then a 500 ms debounce writes all pending notes with one `putMany`; Ctrl+S, `visibilitychange` (hidden) and `pagehide` flush immediately, `beforeunload` asks for confirmation only while writes are pending. One flush at a time; failed writes stay queued and the error stays visible until a write succeeds. The status bar shows the state; only Ctrl+S results, errors and "Nota duplicata" are announced (`announce` in `src/lib/announce.ts`) (live regions sit outside the `inert` content). Pending saves are flushed before a `versionchange` closes the connection (`beforeClose` hook). Creations rolled back by `createNoteInNewTab` are `discardPendingSave`d and never written. Cross-tab (`crossTab.ts`): `BroadcastChannel` messages carry only `{ id, modifiedAt }`, `{ id, deleted }`, `{ savedViews }`, `{ locked }` or `{ reloadAll }` (any replace import, or a merge of more than `RELOAD_ALL_THRESHOLD` notes: other tabs re-list the store and adopt every stored note that differs from memory, even an older one; busy notes get the notice instead, and only ids present before the read count as deleted), never text, titles or tags. Other tabs silently reload a note that is neither active nor dirty there; otherwise they show a notice and **hold** that note's saves (`holdSaves`, status `held`) until the user picks "Carica l’altra versione" (drops local pending changes, bumps `noteRevisions` so the editor is recreated) or "Tieni questa versione" (rewrites with a new `modifiedAt`). Any change that must reach other tabs has to bump `modifiedAt` (pinning does). A note deleted here that comes back from another tab is `allowSaving`'d again. Saved views are read-modify-written and announced with `{ savedViews }`.
- **E2E specs** start every test on a fresh context with `openUnlocked(page)` (creates the passphrase `TEST_PASSPHRASE`, or unlocks in a second tab) and use `reloadUnlocked(page)` instead of `page.reload()` (`e2e/support.ts`). Specs that edit notes register `test.afterEach(({ page }) => waitForPendingSaves(page))` (`e2e/support.ts`): closing a Firefox context with an IndexedDB write in flight can stall the next test's database open for seconds. Stop stray `vite preview` servers before running e2e locally: Playwright reuses whatever answers on port 4173. `playwright.config.ts` blocks service workers by default (`serviceWorkers: 'block'`; `register()` then resolves to `undefined`, which `update.ts` tolerates): a Cache API install in every context made Firefox stall the next test's storage. `offline`, `csp`, `acceptance` and the cross-tab lock test in `vault.spec.ts` set `serviceWorkers: 'allow'` and call `waitForServiceWorker` in `afterEach`. `e2e/acceptance.spec.ts` holds the final acceptance: full journey, settings persistence, a 390×844 phone smoke and an accessibility check without axe (every visible control has an accessible name, no duplicate ids, also inside the editor's shadow root; that's why task-list checkboxes sit in a `<label>` with their text).
- **Tabs** (`src/features/tabs/`): tabs are open notes; closing one never deletes the note. `tabs.ts` holds pure state transitions (`withOpened`/`withClosed`/`withCycled`/`restoreTabs`), `actions.ts` commits them and persists `{ open, active }` in `meta` under key `tabs` (note UUIDs only; tabs of currently unreadable notes are kept hidden, not dropped). Titles come from `noteTitle`/`tabTitle` in `note.ts` (first line, Markdown stripped, 27 chars + "..."). Never put note titles in `document.title`: they would end up in browser history in clear. `TabBar.tsx` follows the ARIA tabs pattern (roving tabindex, arrows/Home/End, Delete closes; the × is mouse-only). Shortcuts: Alt+N new note, Alt+W close tab, Alt+Shift+W close all tabs, Ctrl+Alt+←/→ switch tab. "Chiudi tutte le schede" (`closeAllTabs`, a button at the end of the tab bar after "+ Nuova nota" and a spacer of at least 24px, outside the `tablist`, shown only with open tabs) goes through `closeTabs`: one `meta` write, hidden tabs kept, pending saves untouched, no confirmation; tabs of notes in `changedElsewhere` stay open because they still wait for the user's choice. "Chiudi le schede non fissate" (`closeUnpinnedTabs`, the button just before it, no shortcut, disabled when only pinned or waiting tabs are open) does the same but also keeps pinned notes open. The empty state ("Nessuna nota aperta") lists only the 50 most recent notes and points to Cerca for the rest. New notes open optimistically before the IndexedDB write so fast typing isn't lost; CodeMirror is created in `useLayoutEffect` for the same reason. Alt+N (`createNoteInNewTab`) and "Duplica" (`duplicateNote`) share `openNewNote` in `actions.ts`, which holds the optimistic tab opening, the direct `put` (not autosave), the rollback on failure (tab, memory, pending save, collection filter) and the lock-epoch check; after a successful `put` it posts `{ id, modifiedAt }` with `announceSaved` so other tabs load the new note. If the active filter would hide the new note it falls back to Tutte with the same tags, or with no tags if those would still hide it. "Duplica" in the NoteBar copies the active note's in-memory text (unsaved edits included) into a new note (new UUID and dates, not pinned) with the cursor at the start; `copyText` in `note.ts` appends " (copia)" to the first non-empty line, before any trailing spaces (hard break). When that line can't be extended without changing its Markdown meaning (code fence or indented code, link reference definition, thematic break, table header) "(copia)" goes on its own first line, with the note's own line ending; an empty note becomes "(copia)". `tabTitle` keeps " (copia)" visible when it truncates a long title. No shortcut: Alt+D is the browser address bar.
- **Preview** (`src/features/preview/`): markdown-it with `html: false`, `breaks: true`, linkify; `validateLink` admits only `http`/`https`/`mailto` links and raster `data:image` sources. Remote images become a "Immagine esterna bloccata" notice (no network from note text). Then DOMPurify with closed `ALLOWED_TAGS`/`ALLOWED_ATTR` and a hook forcing `target=_blank rel="noopener noreferrer"`. Table alignment becomes `align-*` classes (inline `style` would violate the CSP); task lists are read-only disabled checkboxes; block tokens carry `data-line` so a double click on the preview puts the cursor on that source line. `tests/preview.test.ts` holds the XSS payloads: add one there for every new markdown feature. View modes (`viewMode.ts`): `edit`/`split`/`preview`, persisted in localStorage (`notepad:view-mode`), Ctrl+E cycles; the editor stays mounted (hidden) in preview-only mode so undo history survives, and creating a note from preview-only switches to split.
- **Collection** (`src/features/collection/`): tags are written in the text (`TAG_PATTERN` in `tags.ts`: `#` + letter, optional `category/name`, lowercased, ignored inside code); categories `cliente`/`progetto`/`tipo`, everything else is "Altri tag". Views (`views.ts`): Tutte, Recenti (7 days), Attività aperte, Fissate, Senza tag, plus saved views stored in `meta` under `savedViews` (they contain tag names, so they are encrypted by the codec like every `meta` value except the keyring). The filter lives only in memory; new notes created with a tag filter get those tags. Delete always goes through the confirmation `<dialog>`; `deleteNote` discards pending saves first and restores them if the delete fails. Modal dialogs (search, delete, settings) are rendered by `Workspace` outside `.app-content`, which becomes `inert`; restore focus with `focusAfterModal`/`deepActiveElement` (`src/lib/focus.ts`) because the editor's focus is inside a shadow root. Sidebar: a column on wide screens (`Ctrl+\` toggles it, remembered in localStorage), an overlay below 1180px. Tag suggestions in the editor use `@codemirror/autocomplete` (`tagCompletion.ts`).
- **Derived data**: `noteInfo(note)` (tags, open tasks, excerpt) and the search index are cached in `WeakMap`s keyed by the immutable `Note` object, so a keystroke recomputes only the edited note (2000 notes of 5 KB: ~2 ms per keystroke). Never mutate a `Note`; replace it. `NoteItem` is a class component with `shouldComponentUpdate`. Search renders at most 50 results.
- **Search** (`src/features/search/`): Ctrl+K, no dependencies, accent/case-insensitive, `#tag` and `is:aperte|fissate|recenti` filters; results are highlighted with `<mark>` built from segments (no HTML). The "index" is normalized text computed on the fly; it lives only in memory (WeakMaps die with the notes, which the lock drops).
- **Transfer** (`src/features/transfer/`, F8): export/import of an encrypted `.notepad` file (UTF-8 JSON, MIME `application/octet-stream`, name `notepad-AAAA-MM-GG.notepad`). Format in `format.ts`: `{ app, kind: "export", version: 1, kdf, wrap, data }` with base64 bytes. The file has its own random AES-256-GCM key, wrapped like the keyring (`wrapKeyWithPassphrase` in `keys.ts`, PBKDF2-SHA-256 600k on the NFC export passphrase, min 12 code points enforced in `sealExport` too) but with AAD `export\0v1`; `data` is ONE AES-GCM encryption (AAD `export-data\0v1`) of `{ notes, savedViews }`, so nothing is in clear (no dates, counts, titles, tags) and per-note sizes are hidden. The local DEK never leaves. Import is strict: 64 MB limit before reading, exact field sets, canonical base64 with exact lengths, iterations in [MIN, MAX], every note with exactly the `Note` fields, a lowercase UUID and integer dates with `0 ≤ createdAt ≤ modifiedAt ≤ now + 24h`, no duplicate ids, views through `parseSavedViews`; a bad unwrap is "Passphrase del file errata" (a tampered wrap/salt looks the same), everything else "non valida" or "versione non supportata". `src/lib/format.ts` never throws on an invalid date (shows `—`). `applyImport` flushes saves, re-reads the store (`repository.snapshot()`: decoded notes + raw records) and plans against the stored versions, not memory (`planImport`, pure): merge adds new notes, the newer `modifiedAt` wins, identical or stored-newer notes are kept; replace deletes the readable notes missing from the file and writes the file's. Ids of unreadable records are never written or deleted (skipped); notes with unsaved/held edits or an open cross-tab notice (`hasLocalConflict`) are never touched, in either mode, and are reported as conflicts, so their edits stay in the save queue (or the vault's encrypted locked queue on lock). Notes and the merged/replaced `savedViews` meta are encoded first, then written in ONE `notes`+`meta` transaction (`repository.applyImport`, all or nothing) that re-reads each target record and skips any that changed since the snapshot (raw record compare, `sameRecord`), counting it as a conflict. Only then memory (`replaceNotes`, `markStored`), tabs (`closeTabs`; replace opens the first imported note), `settleImported` (bumps revisions) and the `savedViews` signal change, and `{ savedViews }` is announced. Every step re-checks the lock epoch; the import path never sets `actionError`. `store.ts` keeps `storedVersion(id)` (last version this tab knows is stored) so `reloadAll` can tell a note changed elsewhere from local unsaved edits. The decrypted payload lives only in the import dialog's state; the dialogs are lazy-loaded (`TransferDialog.tsx`), rendered by `Workspace` and closed when the store stops being ready. The replace confirmation states the number of notes actually removed (`previewImport`), none needed when 0. The download is a temporary `<a download>` with a `blob:` URL appended inside the dialog and removed right after the click (no CSP violation, no network); `e2e/transfer.spec.ts` checks all three.
- **PWA / service worker** (`src/sw/sw.ts`, `src/sw/integrity.ts`, `src/features/pwa/`), no dependencies:
  - `sw.ts` and `integrity.ts` are ES modules for typechecking (own `tsconfig.sw.json`, WebWorker lib; excluded from `tsconfig.json`), but `sw.js` must be a classic script: the `notepad:sw` plugin in `vite.config.ts` (build only, `writeBundle`) concatenates `integrity.ts` without `export` and `sw.ts` without `import`, transpiles them with `typescript`, refuses output that still has `import`/`export`, and prepends `SW_PRECACHE` (every file in `dist/` except `sw.js` as `[path, sha256base64]`, paths relative to the scope, so it works under `/notepad-minus-minus/` and `/`) and `SW_CACHE_NAME` (`notepad-minus-minus-` + hash of the file hashes). Keep `integrity.ts` pure and import-free: `tests/integrity.test.ts` tests it directly.
  - It caches **only the app's own static files, never note data**; IndexedDB is untouched. Fetch answers only same-origin GETs inside the scope: navigations to the app page get `index.html`, precached files are cache-first with network fallback, nothing else is cached at runtime. No `importScripts`, no external URLs.
  - **Integrity**: CacheStorage is per origin, so any page on `lucamilan.github.io` can write into our cache. The SW therefore verifies the SHA-256 of every file against `SW_PRECACHE` at install (fetched with `cache: 'reload'`; a missing or mismatching file fails the install, so a half-published deploy keeps the previous version active) and **on every response it serves**, `index.html` included (`serveVerified`: a bad cached entry is deleted and refetched; the network copy is served and re-cached only if it matches, otherwise a 503 text). Results are never memoized, since the cache can change underneath; the cost is ~1–2 ms of SHA-256 for the 490 KB Workspace chunk (measured in Chromium/Firefox). Served responses are rebuilt with the verified body and headers chosen by the SW (`contentTypeFor`, `nosniff`), so headers in a planted entry don't pass either. What the shared origin can still do: delete our caches or unregister the SW, which only degrades to the network (and offline to the browser error); it cannot register a worker for our scope without a script under our path. Activate deletes only older `notepad-minus-minus-*` caches. Old tabs that need a lazy chunk of their (deleted) version get the existing "Ricarica la pagina" message: serving from the previous cache was rejected because the old hashes could only come from storage the shared origin can also write.
  - Updates: no `skipWaiting` on install. `update.ts` (browser APIs injected, unit-tested in `tests/update.test.ts`) sets `updateState`; `UpdateBanner` ("È disponibile una nuova versione", non-modal, `role="status"` region always mounted, rendered by `App` on the lock screens and the workspace). "Aggiorna" runs `settleBeforeReload` (`vault.ts`: waits for an unlock and a lock in progress, flushes saves; `resumeLockedQueue` empties `lockedQueue` only after the notes are back in `scheduleSave`, so the beforeunload guards never drop), posts `{ type: 'SKIP_WAITING' }` (the SW accepts only that exact object from a same-origin window client) and reloads once on `controllerchange`; if that doesn't happen within 5 s (`UPDATE_FALLBACK_MS`) or the waiting worker turns `redundant`, it reloads anyway and re-enables the buttons. While locked with edits held at lock (`lockedQueueCount > 0`, only savable after unlocking) the banner adds "Sblocca per salvare le modifiche prima di aggiornare" and disables "Aggiorna". "Più tardi" restores focus to the last element focused outside the banner (or the passphrase field / the active note's editor). If another tab activated the new version, the banner shows and "Aggiorna" just reloads. Updates are also checked when the tab becomes visible, at most once an hour. The banner is the way users get fixes.
  - Registration only in production (`import.meta.env.PROD`) and when `'serviceWorker' in navigator`; errors are logged and the app keeps working. `npm run dev` never registers one; a worker left on localhost by `npm run preview` stays until removed in DevTools (Application → Service workers).
  - `public/manifest.webmanifest` (relative URLs) and `public/icons/` (generated once from `favicon.svg` and a padded maskable variant). `e2e/offline.spec.ts` covers offline unlock and editing, cache poisoning from the same origin, the update flow (a private Node server serving a changed `sw.js`, because Playwright routes don't intercept service worker scripts) and the manifest.
- **Shared origin**: every page under `lucamilan.github.io/*` is same-origin with this app and can read or alter its IndexedDB, and script it while unlocked. F7 encryption protects confidentiality at rest, not integrity nor an unlocked session. This is an accepted GitHub Pages limit unless the app moves to a dedicated domain.
- **No HTML into the DOM** except from `renderMarkdown` in `src/features/preview/markdown.ts`, which returns already-sanitized nodes (DOMPurify `RETURN_DOM_FRAGMENT`) inserted with `replaceChildren`. ESLint blocks `innerHTML`, `outerHTML`, `insertAdjacentHTML` and `dangerouslySetInnerHTML`. Preact renders via `createElement`, which is why it was chosen over Svelte/Solid.
- **No network**: no CDNs, no external fonts (self-host them), no analytics, no remote images in notes. Links in notes open with `noopener noreferrer`. The only requests are for the app's own files (and the browser's service worker update check).
- **Encryption at rest** (`src/features/crypto/`, Web Crypto only):
  - Keys (`keys.ts`): a random AES-256-GCM data key (DEK) encrypts notes and `meta` values; it is stored only wrapped (`wrapKey('raw', …, AES-GCM)`) by a KEK derived with PBKDF2-SHA-256, `PBKDF2_ITERATIONS` = 600 000, 16-byte random salt, from `passphrase.normalize('NFC')` in UTF-8. The KEK is non-extractable (wrapKey/unwrapKey only); the DEK in use is unwrapped non-extractable (encrypt/decrypt) and lives only inside the codec closure (never in a signal or storage). A wrong passphrase is detected by `unwrapKey` failing GCM authentication (`WrongPassphraseError`). Minimum passphrase length 12 code points.
  - Keyring: clear in `meta` under `keyring`: `{ version: 1, kdf: { name: 'PBKDF2', hash: 'SHA-256', iterations, salt }, wrap: { iv, key } }`, validated strictly by `parseKeyring` (accepts `MIN_PBKDF2_ITERATIONS` (600 000) to 10 000 000 iterations, separate from the creation count `PBKDF2_ITERATIONS`; unit tests lower it only through explicit test options, never through stored data). Setup writes it with `add` (atomic across tabs: the loser shows "La passphrase è già stata creata in un’altra scheda").
  - Changing the passphrase re-wraps the same DEK with a new KEK (new salt) in one `meta` put: atomic, instant, safe with several tabs. Trade-off: the DEK is not rotated, so whoever has both an old copy of the database and the old passphrase can still read it. There is no recovery: "Ho dimenticato la passphrase" (type ELIMINA) deletes the encrypted database.
  - Codec `aesgcm-v1` (`aesCodec.ts`): payload `{ iv (12 random bytes per record), data }`, plaintext = JSON of the note without `id`; additional data `note\0<id>\0aesgcm-v1` (meta: `meta\0<key>\0aesgcm-v1`) so a ciphertext can't move to another record. Decode failures are `CorruptNoteError`; never log plaintext.
  - Legacy migration (`legacy.ts`): after setup and after every unlock, the old DB `notepad-minus-minus` is opened at `version + 1` (an upgrade that changes nothing) so open F2–F6 tabs flush their queue on `versionchange` and close before the snapshot is read; if it stays blocked for more than 10 s nothing is touched and it is retried at the next unlock. Readable notes are encrypted (before opening the write transaction); for ids already in the new DB the newer `modifiedAt` wins. Imported ids and dates are kept encrypted in `meta.legacyImported`, so a note deleted after import never comes back. Then the old DB is deleted in the background; if some records are unreadable it is kept and Settings shows "Note non cifrate rimaste (illeggibili)" with a confirm-to-delete (`legacyLeftover`). `tabs`/`savedViews` are carried over only at setup. The v1 Blazor database `SqliteStorage` is never deleted automatically: Settings offers "Elimina i dati della v1…" with a confirm dialog.
  - Lock (`lockVault`): the lock screen replaces the workspace at once (editor, preview, dialogs unmount), pending saves are flushed, notes that still fail to write are kept already encrypted in a module queue and resumed after the next unlock (a newer version saved elsewhere wins and the held text becomes a new note). Notes held for a cross-tab conflict always come back as a new copy. Then each module's `reset…ForLock` drops notes, tabs, hidden tabs, saved views, filter, delete/search requests, cross-tab notices and revisions, the autosave queue and status, the repository and the codec's key. The DB connection stays open (it holds no key). Triggers: "Blocca" in the AppBar / Alt+L / "Blocca ora" in Settings (broadcast `{ locked: true }`, other tabs lock too), inactivity auto-lock (`autoLock.ts`: 5/15/30/60 minutes, default 15, localStorage `notepad:auto-lock`; activity = pointerdown/keydown/wheel/touchstart + editor input; checked by timer and on visibilitychange/focus comparing timestamps; per tab, no broadcast). While locked, note messages from other tabs are ignored. A lock requested during an unlock (`unlocking.lockRequested`) is applied when loading ends: the vault stays locked and what was loaded is dropped; "Ho dimenticato la passphrase" is refused during an unlock. `resetNotesForLock` bumps a lock epoch (`currentLockEpoch()` in `store.ts`): every continuation after an `await` that touches notes, saved views or the save queue (delete, cross-tab reload, load-latest, create) must check it and bail out if it changed, so no plaintext comes back after a lock.
  - Vault state (`vaultState`: `opening` | `setup` | `locked` | `unlocked` | `error`) drives `App`; when unlocked, `initNotes` loads the notes with the AES codec.
- **Code splitting**: `App.tsx` is a thin shell; everything shown with notes unlocked lives in `src/app/Workspace.tsx`, loaded with `import()` (`lazyWorkspace.ts`) in parallel with the PBKDF2 derivation. The lock screens (`src/features/crypto/VaultScreen.tsx` and what it imports) must never import the workspace, CodeMirror, markdown-it, DOMPurify or the collection UI: only small state modules (signals) are shared. `e2e/csp.spec.ts` asserts the Workspace chunk isn't requested before unlocking.
- **Dependencies**: add one only when a feature really needs it, pin the exact version, and choose a release at least 14 days old (Dependabot uses the same cooldown).
- Code layout: `src/app` (shell UI), `src/features/<feature>` (notes, tabs, editor, preview, collection, search, crypto, transfer, settings, pwa), `src/sw` (service worker), `src/lib` (shared utilities). Create folders only when they get code.

## Deployment

`.github/workflows/pages.yml` runs on push to `main`: lint, unit tests, `vite build` with `BASE_PATH=/notepad-minus-minus/`, then pushes `dist/` to the root of the `gh-pages` branch (`JamesIves/github-pages-deploy-action`, `clean: true`). The v2 replaced v1 at the site root from F0 onward. `ci.yml` runs the full checks (format, lint, typecheck, unit, build, e2e) on every PR. Actions are pinned by commit SHA.
